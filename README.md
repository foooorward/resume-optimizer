# 简历优化工作台

粘贴岗位 JD → 填写个人信息 → 自动生成岗位匹配度评估与优化建议 → 导出适配该岗位的简历。

单文件静态应用：HTML + CSS + JavaScript 全部内联，**零外部依赖、零构建、零后端**，双击 `index.html` 就能用，也可以托管到任意静态服务器。

## 文件结构

```

├── index.html   # 全部源码（约 2700 行，含样式、逻辑、词库）
├── README.md    # 本文件
```

## 推送到 Gitee

在 Gitee 新建一个仓库（建议公开），然后在本目录执行：

```bash
git init
git add .
git commit -m "feat: 简历优化工作台"
git branch -M master
git remote add origin https://gitee.com/<你的用户名>/<仓库名>.git
git push -u origin master
```

> 若已存在远程仓库，可跳过 `git init` / `remote add`，直接 `git add . && git commit && git push`。

## 在线访问怎么做（重要）

先说结论：**Gitee 本身已经无法生成可访问的网页链接了**，原因有两个，都是平台限制，不是配置问题：

1. **Gitee Pages 已下线** —— 官方在 2025 年的 issue 中确认该功能已下线，仓库「服务」菜单里不再有入口，`*.gitee.io` 域名也不再对新仓库开放。
2. **Gitee 原始文件链接不能渲染页面** —— `https://gitee.com/<用户>/<仓库>/raw/master/index.html` 返回的响应头是 `Content-Type: text/plain`，浏览器只会把它当纯文本显示源码，不会渲染。jsDelivr 这类免费 CDN 也只支持 GitHub / npm，不支持 Gitee。

所以 Gitee 只能承担**源码托管**的角色。要给别人一个能直接打开使用的链接，需要把它接到一个静态托管平台上。

### 腾讯云 EdgeOne Pages（支持直接导入 Gitee 仓库）

国内免费、有 CDN 加速，是少见的**原生支持从 Gitee 仓库导入**的托管平台（同类平台一般只支持 GitHub / GitLab）。

导入步骤：

1. 登录腾讯云控制台，搜索进入 **EdgeOne**，在「计费管理 → 套餐管理」领取**免费版套餐**（免费）
2. 左侧菜单选 **Pages** → **创建项目** → 选择 **导入 Git 仓库**
3. 绑定 **Gitee** 账号并授权，选中本仓库 `resume-optimization`
4. 构建配置（本项目是纯静态、无需构建）：
   - 框架预设：选「其他」或不选
   - 构建命令：**留空**
   - 输出目录：填 `/`
5. 点击部署，约 1 分钟完成

之后每次 `git push` 到 Gitee，EdgeOne 会自动重新部署。

> ⚠️ **接入 Git 仓库只解决「自动部署」，不会给你永久域名** —— 域名这件事绕不过去，见下一节。

### ⚠️ 重要：EdgeOne 的默认域名**不能**长期对外分享

这一点我实际部署验证过，也核对过官方文档，必须说清楚，否则很容易踩坑。

EdgeOne Pages 有两类默认域名：**项目域名**（固定的 `*.edgeone.app`）和**部署域名**（每次部署一个 `*-<hash>.edgeone.cool`）。这两类域名能不能直接访问，由项目的**加速区域**决定：

| 加速区域 | 默认域名（项目域名 / 部署域名） | 绑定自定义域名 |
| --- | --- | --- |
| 中国大陆可用区 | **必须用系统生成的预览链接访问，有效期 3 小时，超时返回 401** | 需工信部备案 |
| 全球可用区（含中国大陆） | 同上，3 小时后失效 | 需工信部备案 |
| 全球可用区（不含中国大陆） | 非中国大陆可直接访问；**中国大陆访问返回 401** | **无需备案** |

实测印证：部署后拿到的链接形如

```
https://<项目名>-<hash>.edgeone.cool?eo_token=<token>&eo_time=<时间戳>
```

去掉 `?eo_token=...&eo_time=...` 这段查询参数，立刻变成 401 Unauthorized。控制台「项目概览」右上角的**「预览」按钮**可以随时刷新出一个新的 3 小时有效链接——但每次都要手动刷新，**没法把一条链接长期发给别人**。

**所以要得到一个稳定、长期可打开的链接，只有一条路：绑定自己的域名。**

- 域名**已备案** → 加速区域选「中国大陆可用区」，国内直连最快
- 域名**没备案** → 加速区域改选「全球可用区（不含中国大陆）」，**不需要备案**；绑上自定义域名后国内也能正常访问（走海外节点，速度一般）

操作路径：控制台 → EdgeOne → **Pages** → 选中项目 → **项目设置 → 域名管理 → 添加自定义域名** → 按提示到 DNS 服务商加一条 CNAME 记录（可勾选免费自动签发 SSL 证书）。

> 不需要自动部署的话，也可以用 EdgeOne 的 **Pages Drop**：把 `index.html` 直接拖进上传框，几秒出链接，不用接 Git（未注册账号时该链接只有 1 小时有效）。

### 只想本地先用

直接双击 `index.html` 即可。如遇浏览器限制，可在本目录执行 `python -m http.server 8000`，然后访问 `http://localhost:8000`。

## 数据存放在哪里

简历数据保存在**浏览器的 localStorage**（键名 `wb_resume_workspace_v1`），不经过任何服务器：

- 同一浏览器、同一地址下数据长期保留，清空浏览器数据会丢失；
- 换设备 / 换浏览器不会自动同步；
- 右上角「导出备份」可下载 JSON 快照，「导入恢复」可把快照导回（也能导入到另一台设备）。

页面右上角的模式徽标会显示 `本地存储`。如果把它放回 WorkBuddy 资料库环境，代码会自动识别并切换为云端数据表同步（徽标显示 `已同步`），两种模式共用同一套逻辑，无需改动。

> **把这个链接发给别人时请注意**：因为数据存在**每个访问者自己的浏览器**里，别人打开链接看到的是内置示例数据和他自己填的内容，**看不到你填的简历**；你在自己浏览器里填的内容也只有你自己能看到（换设备需靠导出/导入 JSON 转移）。它分享的是**工具本身**，不是某一份简历。

## 技术说明

- 优化能力由内置规则引擎实现：技能词库匹配 + 弱动词替换 + 量化检测 + 结构体检，**不调用任何大模型接口**，因此不会有网络请求，也不会产生使用费用。
- 所有渲染到页面的动态内容（用户输入、导入数据）均经过 `esc()` 做 HTML 转义后拼接，避免 XSS。
- 无 Cookie、无埋点、无第三方脚本，打开页面不发任何外部请求（可用浏览器开发者工具的网络面板验证）。
